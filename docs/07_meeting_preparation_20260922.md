## 1. AS-IS 프로세스 구체화

**AS-IS = ERP 도입 전 고객사의 현재 업무 방식.** 3주차 보고서에 나온 전화·이메일·엑셀 기반 업무를 단백질바 주문 한 건의 흐름으로 연결하였다.

1. **주문:** 영업팀이 유통업체의 카카오·모카·솔티드 캐러멜 단백질바 주문을 전화나 이메일로 접수하고 엑셀에 입력한다.
2. **재고 확인:** 영업팀이 창고에 완제품 재고를 문의한다. 재고 및 생산예정 수량을 즉시 확인하기 어려워 납기 확정이 늦어지거나 잘못될 수 있다.
3. **생산:** 생산팀은 전달받은 출고 요청에 맞춰 필요한 맛의 생산량을 정한다. 원재료와 반제품 수량은 별도 파일·작업일지로 확인한다.
4. **구매·입고:** WPC80, 식이섬유, 바인더 베이스, 크리스프, 맛별 향미 프리믹스 등이 부족하면 구매팀이 긴급 발주한다.
5. **제조·포장:** 원료 계량·프리믹스 → 바인더 제조·최종 혼합 → 냉각성형·냉각·절단 → 맛별 인쇄필름 개별 포장 순으로 생산한다.
6. **출고·정산:** 포장된 제품을 출고하고, 판매·구매·원가 자료를 각 담당자가 따로 취합하여 회계·원가를 정리한다.

**핵심:** 영업 주문, 맛별 재고, 원재료 구매, 생산, 출고·회계가 하나의 데이터 흐름으로 연결되지 않는 상황을 AS-IS의 중심으로 설정한다.

## 2. AS-IS 프로세스 기반 문제점 분석

| 문제 | 머슬앤허슬의 구체적인 상황 | 개선 방향 |
|---|---|---|
| 주문·재고 정보 분리 | 모카바 100개를 주문받았으나 실제 완제품 재고는 부족한데도 납기를 확정 | 맛별 자재코드로 주문·재고·납기 확인 |
| 원재료 부족·긴급구매 | 카카오바 생산 직전에 카카오 향미 프리믹스 부족을 발견 | 맛별 BOM에 필요한 원재료를 연결하고 생산 전 소요량 확인 |
| 생산계획의 잦은 변경 | 단기 출고요청으로 카카오→모카 등 생산순서가 반복적으로 바뀌어 세척·설정시간 증가 | 판매수요와 생산·자재계획을 함께 검토 |
| 실제원가 파악 지연 | 맛별 원료 투입량·폐기량·작업시간을 따로 집계해 제품별 원가 비교가 어려움 | 생산오더와 자재 투입·작업 데이터를 연결해 원가 비교 |

### 단백질바 산업에 맞춘 추가 문제 2가지

**① 맛별 인쇄필름 부족:** 카카오 미포장 바는 충분하지만 카카오 전용 필름이 부족하면 포장된 완제품으로 출고할 수 없다. 따라서 맛별 인쇄필름을 포장재(VERP)로 별도 관리하고 해당 맛의 완제품 BOM과 연결하는 방안을 제안한다.

**② 맛 전환 시 생산지연:** 제품 맛을 바꿀 때 원료 준비·설비 세척·설정시간이 발생한다. 영업팀이 이 시간을 고려하지 않고 납기를 확정하면 출고 지연이 생길 수 있다. PP 생산일정과 SD 납기 확인을 연결하는 방안을 제안한다.

*위 상황은 보고서의 문제를 구체화한 가상 고객사 시나리오이며, 실제 기업에서 관측된 수치나 사건은 아니다.*

## 3. 각 모듈의 업무 흐름

| 모듈 | 간단한 역할 | 머슬앤허슬 사례 |
|---|---|---|
| **SD** 영업·판매 | 고객 주문부터 출고·청구까지 | 카카오바 100개 수주 → 재고·납기 확인 → 납품·청구 |
| **PP** 생산 | 무엇을 얼마나 어떻게 만들지 관리 | 카카오바 100개 생산계획, BOM·공정 확인 |
| **MM** 구매·자재 | 원재료 구매·입고·재고 관리 | WPC80·카카오 프리믹스·카카오 인쇄필름 구매·재고 확인 |
| **FI** 재무회계 | 거래를 장부에 기록 | 원재료 구매대금·고객 매출채권 처리 |
| **CO** 관리회계 | 원가와 수익성 파악 | 카카오·모카·솔티드 캐러멜 바의 생산원가 비교 |

**판매 주문 1건으로 연결한 흐름:** SD에서 주문 접수 → PP에서 부족 수량 생산계획 → MM에서 부족 원료·포장재 구매 → PP에서 생산 → SD에서 출고·청구 → FI에서 회계 처리 → CO에서 원가 확인.

이 흐름은 **업무가 연결되는 개념도**다. 주문 입력만으로 구매오더·생산오더가 자동으로 생긴다는 뜻은 아니며, SAP 실습에서 자동화할 범위는 별도로 확인한다.

## 4. 모듈별 조직구조 설계

처음부터 여러 국가·공장을 만들기보다는 **국내 법인 1개, 공장 1개**를 기준으로 시작하는 안이다.

| 모듈 | 필요한 조직·데이터 | 구성 제안 |
|---|---|---|
| FI | Company Code(회사코드) | 머슬앤허슬 국내 법인 1개 |
| CO | Controlling Area(관리회계영역), Cost Center(원가센터) | 관리회계영역 1개, 생산·영업 비용을 구분할 원가센터 검토 |
| MM | Plant(공장), Storage Location(저장위치), Purchasing Organization(구매조직) | 공장 1개, 원재료·반제품·완제품 저장위치, 국내 구매조직 1개 |
| PP | Plant, Work Center(작업장), Routing(공정순서) | 같은 공장에 보고서상 4개 생산공정 설정 |
| SD | Sales Organization(영업조직), Distribution Channel(유통경로), Division(제품군), Shipping Point(출하지점) | 국내 영업조직 1개, 도매 중심·온라인 확장, 제품군 '단백질바' 1개, 공장 출하지점 1개 |

### SD 조직구조 제안

- **영업조직:** 국내 영업조직 1개.
- **유통경로:** 1차는 유통업체에 납품하는 **도매(B2B)**로 설정. 온라인 판매는 기본 판매 흐름을 구현한 뒤 확장 여부 결정.
- **제품군:** 단백질바 1개. 카카오·모카·솔티드 캐러멜은 제품군을 셋으로 나누지 않고 **완제품 자재코드 3종**으로 구분.
- **출하지점:** 생산공장에서 완제품을 출고하는 지점 1개.
- **판매영역(Sales Area):** 영업조직 + 유통경로 + 제품군의 조합.

**제안 이유:** 고객·제품·공장 연결을 단순하게 만들어 SD에서 주문→납품→출고→청구의 기본 흐름을 먼저 확인할 수 있다. 실제 생성 가능 조직코드와 수업 요구범위는 SAP 시스템·팀원과 확인한다.

## 5. 자재마스터 구체화

**자재마스터 = 제품·원재료마다 등록하는 기본정보.** 오늘은 보고서에 제시된 자재의 **이름 / 유형(Type) / 기본단위(UoM) / 개수**를 먼저 맞추고, **자재그룹 및 평가클래스**를 결정하면 된다.

### 5-1. 원재료(ROH) — 7종

| 자재명 | 유형 | 기본단위 | 구분 |
|---|---|---|---|
| 유청단백질농축물 WPC80 | ROH | KG | 공통 원료 |
| 수용성 식이섬유 | ROH | KG | 공통 원료 |
| 단백질바용 바인더 베이스 | ROH | KG | 공통 원료 |
| 단백질 크리스프 | ROH | KG | 공통 원료 |
| 카카오 향미 프리믹스 | ROH | KG | 맛별 원료 |
| 모카 향미 프리믹스 | ROH | KG | 맛별 원료 |
| 솔티드 캐러멜 향미 프리믹스 | ROH | KG | 맛별 원료 |

**구성 제안:** 공통 원료 4종을 공유하고 향미 프리믹스 1종을 맛에 따라 다르게 투입한다. 실제 투입 중량은 아직 결정되지 않았다.

### 5-2. 반제품(HALB) — 보고서안 7종

| 반제품 | 유형 | 기본단위 |
|---|---|---|
| 공통 단백질 프리믹스 | HALB | KG |
| 카카오 / 모카 / 솔티드 캐러멜 단백질바 반죽 | HALB | KG |
| 미포장 카카오 / 모카 / 솔티드 캐러멜 단백질바 | HALB | EA |

**논의할 점:** 보고서의 7종을 모두 별도 생산·재고로 관리하면 BOM과 생산오더도 복잡해질 수 있다. **독립적으로 재고에 보관할 반제품만 등록하고 나머지는 생산공정 중간단계로 설명할지**, PP 담당자와 구현 범위를 결정한다. 보고서 목록 자체는 임의로 삭제하지 않는다.

### 5-3. 완제품(FERT) — 맛 3종

| 완제품명(정정 제안) | 유형 | 판매단위 |
|---|---|---|
| M&H 카카오 크런치 단백질바 | FERT | EA |
| M&H 모카 크런치 단백질바 | FERT | EA |
| M&H 솔티드 캐러멜 크런치 단백질바 | FERT | EA |

*보고서의 완제품 표에는 카카오가 중복되고 솔티드 캐러멜 브랜드명이 'M&G'로 표기되어 있어 정정 여부 확인 필요.*

**추가 결정:** 바 1개의 중량(g), 생산할 기준 수량, 맛별 원료 투입량. 이 값이 있어야 BOM 수량과 반죽 KG → 미포장 바 EA 환산을 정할 수 있다.

### 5-4. 상품(HAWA) — 2종

| 상품 | 유형 | 단위 |
|---|---|---|
| M&H 셰이커 보틀 | HAWA | EA |
| M&H 스포츠 타월 | HAWA | EA |

**포함 여부 제안:** 이 두 상품은 직접 생산하지 않고 외부에서 구매해 재판매한다. 먼저 **단백질바 제조·판매 흐름을 구현하고**, 추가 시나리오가 필요하면 상품 구매(MM)·판매(SD)를 붙이는 방식으로 결정한다.

### 5-5. 포장재(VERP) — 4종

| 포장재 | 유형 | 기본단위 |
|---|---|---|
| 카카오 크런치 인쇄필름 | VERP | M |
| 모카 크런치 인쇄필름 | VERP | M |
| 솔티드 캐러멜 인쇄필름 | VERP | M |
| 공용 골판지 운송박스 | VERP | EA |

**추가 결정:** 개별 바 1개당 인쇄필름 사용길이(M), 운송박스 1개당 들어가는 바의 개수(EA). 맛별 필름을 해당 맛의 BOM에 넣되, 운송박스는 생산용 포장인지 출하용 포장인지 먼저 구분한다.

### 5-6. 자재그룹과 평가클래스는 다르다

| 항목 | 쉽게 말하면 | 결정 방향 |
|---|---|---|
| **자재유형(Type)** | 원재료인지, 반제품인지, 완제품인지 구분 | ROH / HALB / FERT / HAWA / VERP |
| **자재그룹(Material Group)** | 비슷한 자재끼리 묶는 관리용 분류 | 공통 원료·향미 원료·반제품·완제품·상품·포장재 등 제안 |
| **평가클래스(Valuation Class)** | 재고금액이 연결될 회계계정 구분 | 실제 SAP에서 허용된 값을 **FI·MM 담당자와 확인 후** 확정 |

평가클래스 숫자는 3주차 보고서에 기재되지 않았다. 임의 번호를 확정값으로 넣지 않는다.

## 6. 네이밍 룰(코드 규칙) 제안

코드만 보아도 **어느 회사의 조직인지 / 어떤 종류의 자재인지 / 어느 맛인지** 알 수 있도록 통일한다.

### 조직코드(제안)

| 조직 | 코드 | 의미 |
|---|---|---|
| Company Code | MH01 | 머슬앤허슬 국내 법인 |
| Plant | MH10 | 생산공장 |
| Purchasing Organization | MH20 | 구매조직 |
| Sales Organization | MH30 | 영업조직 |
| Shipping Point | MH40 | 출하지점 |
| Controlling Area | MH50 | 관리회계영역 |

### 자재코드(제안)

| 자재 | 코드 예시 |
|---|---|
| 유청단백질농축물 | RM-WPC-001 |
| 카카오 / 모카 / 솔티드 캐러멜 향미 프리믹스 | RM-CCA-001 / RM-MOC-001 / RM-SCA-001 |
| 공통 단백질 프리믹스 | SF-COM-001 |
| 카카오 / 모카 / 솔티드 캐러멜 완제품 | FG-CCA-001 / FG-MOC-001 / FG-SCA-001 |
| 카카오 / 모카 / 솔티드 캐러멜 인쇄필름 | PK-CCA-001 / PK-MOC-001 / PK-SCA-001 |
| 셰이커 보틀 / 스포츠 타월 | TG-SHK-001 / TG-TWL-001 |

**코드 원칙:** RM=원재료, SF=반제품, FG=완제품, PK=포장재, TG=상품 / CCA=카카오, MOC=모카, SCA=솔티드 캐러멜. 실제 SAP의 코드 길이·형식·기존 코드와 충돌하지 않는지는 적용 전에 확인한다.

## 오늘 회의에서 결정할 사항
